# Baseline Provenance And Certification

Status: Accepted.

Portable report comparisons will distinguish baseline integrity from certification. A baseline can pass manifest, checksum, schema, and row-count validation without certifying that the portable report flow independently reproduced a trusted current report. A comparison is certifying only when `expected-report.json` comes from an independent trusted current output. Expected reports generated by the portable wrapper, seed placeholders, or unknown provenance produce provisional comparisons even when field comparison passes.

## Considered Options

- Treat any `comparison.status == passed` result as a certified reproduction.
- Keep wrapper-generated expected reports for scaffolding, but mark them as provisional.
- Require independent expected-report provenance for certified comparison status.

## Consequences

- Tests and smoke fixtures can still prove command wiring and artifact handling.
- User-facing docs must not imply certification unless expected-report provenance is independent.
- Future exporter work should prefer exporting the trusted current report output directly when available.
